# Spike S2: Cloudflare Quick Tunnel (`cloudflared`), DoH warm-up and a 15-minute WebSocket

Date: 2026-11-13
Goal: verify the quick start of the free `cloudflared` tunnel, the absence of local DNS cache leaks during the readiness check (via DoH), the stability of a WebSocket connection over 15 minutes, and the behavior when the tunnel process drops and is restarted.

## 1. Verified version and scenario

- Client: `cloudflared version 2025.11.1 (built 2025.11.07-16:59 UTC)`
- Check command: `bun run spikes/s2-tunnel.ts --hold-sec 900`
- Sequence:
  1. Bring up a local HTTP + WebSocket server on `127.0.0.1` (`/healthz` + `/ws`).
  2. Start `cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate`.
  3. Check DNS through DoH (`cloudflare-dns.com`, with a fallback to `dns.google`) until an A/AAAA record for `*.trycloudflare.com` appears.
  4. Poll the public `/healthz` until it answers `200 ok`.
  5. Open a WSS connection over the tunnel and send a `ping` every 20 s for 900 s.
  6. Forcibly terminate `cloudflared` and automatically restart it, measuring the repeated warm-up.

## 2. Observed results (live run)

| Metric                                  | Value                                                                |
| --------------------------------------- | -------------------------------------------------------------------- |
| First tunnel (DoH ready)                | **4,494 ms** (~4.5 s)                                                |
| First tunnel (`/healthz` 200 OK)        | **4,847 ms** (~4.8 s)                                                |
| WebSocket `ping` / `pong` over 15 min   | **45 / 45** (`wsClosedUnexpectedly: false`, duration **900,224 ms**) |
| Second tunnel after `kill` (DoH)        | **4,454 ms** (~4.5 s)                                                |
| Second tunnel after `kill` (`/healthz`) | **4,855 ms** (~4.9 s)                                                |
| WS reconnection                         | **Succeeded** (`reconnectedOk: true`, `errors: []`)                  |

## 3. Conclusions for the implementation (`server/tunnel/cloudflared.ts`)

- When `cloudflared` is restarted, the quick tunnel issues a **new** `*.trycloudflare.com` subdomain: the old `inviteUrl` is not preserved, so on an automatic tunnel restart the host must update the invitation banner (`tunnel_updated`, with the `changedSinceStart` flag marking an address change during the game).
- The DoH warm-up (`cloudflare-dns.com` → `dns.google`) takes ~4.5 s and avoids negative `NXDOMAIN` caching in the OS until the record has actually propagated.
- Up to 3 automatic restarts are provided when `cloudflared` crashes (backoff 2 s / 5 s / 10 s), as well as a clean shutdown by process group when the server stops; the manual fallback is to start the server with `--public-url` or `--no-tunnel`.
