# Спайк S2: Cloudflare Quick Tunnel (`cloudflared`), DoH-прогрев и 15-минутный WebSocket

Дата: 2026-11-13
Цель: проверить быстрый запуск бесплатного туннеля `cloudflared`, отсутствие утечек локального DNS-кэша при проверке готовности (через DoH), стабильность WebSocket-соединения в течение 15 минут и поведение при обрыве и перезапуске процесса туннеля.

## 1. Проверенная версия и сценарий

- Клиент: `cloudflared version 2025.11.1 (built 2025.11.07-16:59 UTC)`
- Команда проверки: `bun run spikes/s2-tunnel.ts --hold-sec 900`
- Последовательность:
  1. Подъём локального HTTP + WebSocket сервера на `127.0.0.1` (`/healthz` + `/ws`).
  2. Запуск `cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate`.
  3. Проверка DNS через DoH (`cloudflare-dns.com`, с fallback на `dns.google`) до появления A/AAAA записи `*.trycloudflare.com`.
  4. Опрос публичного `/healthz` до ответа `200 ok`.
  5. Открытие WSS-соединения поверх туннеля и отправка `ping` каждые 20 с в течение 900 с.
  6. Принудительное завершение `cloudflared` и автоматический перезапуск с измерением повторного прогрева.

## 3. Выводы для реализации (`server/tunnel/cloudflared.ts`)

- При перезапуске `cloudflared` quick tunnel выдаёт **новый** поддомен `*.trycloudflare.com`: старый `inviteUrl` не сохраняется, поэтому при авто-рестарте туннеля хост должен обновлять баннер приглашения (`tunnel_updated`, с отметкой смены адреса во время игры `changedSinceStart`).
- Прогрев через DoH (`cloudflare-dns.com` → `dns.google`) занимает ~4.5 с и позволяет избежать негативного кэширования `NXDOMAIN` в ОС до момента фактического распространения записи.
- Предусмотрено до 3 авто-перезапусков при падении `cloudflared` (backoff 2 с / 5 с / 10 с) и корректное завершение по группе процессов при остановке сервера; ручной запасной вариант — запуск сервера с `--public-url` или `--no-tunnel`.
